# D8K-1 — 모든 추천 상품 공통 판매처 가격 비교 기능의 기초 로직

> 기준일 2026-10-14 · 상태: **비교 계산 구현 / 가상 데이터 CI 검증 / 실제 판매처 연동 HOLD**
> 관련: [전체 보수 로드맵](r16i-r4-d8k-universal-offer-remediation-roadmap-20261014.md), [활성 추천 화면 조사](r16i-r4-d8k0-active-recommendation-surface-and-price-baseline-20261014.md).
> 사용자 확정: 공식몰·쿠팡·올리브영·화해 우선, **모든 추천 상품**에 동일 규칙. 다른 판매처 추가 가능.

## 1. 쉽게 말해 이번에 구현한 것

**상품별 판매처 가격 비교표를 만들 때, 무엇을 서로 비교해도 되는지 판단하는 공통 계산기**를 구현했습니다. 아직 무료·프리미엄 결과 화면에 구매처 버튼이 새로 나타나는 단계가 아닙니다.

예시 (아래는 **모두 가상 테스트 금액**, 실제 판매 가격 아님):

- 동일 80ml 단품: 공식몰 24,500원, 올리브영 22,500원(+배송비 3,500원), 화해 23,500원, 쿠팡 22,000원(배송비 미확인).
- **선택한 옵션의 가격만** 정렬하면 쿠팡 22,000원부터지만, 배송비가 미확인이므로 **'최종 결제 최저가'라고 표시하지 않습니다.**
- 쿠팡 배송비가 4,000원으로 확인되면 그때 배송비까지 합산해 화해 23,500원, 공식몰 24,500원, 쿠팡 26,000원, 올리브영 26,000원 순으로 정렬할 수 있습니다.
- **80ml 2개+세럼 증정 기획세트 29,900원**은 단품 80ml와 **다른 비교 묶음**입니다. '더 저렴한 80ml 단품'으로 오인하지 않습니다.
- 실제 상품 추천 순위와 피부 적합도 점수는 전혀 변경하지 않습니다.

## 2. 실제 코드 변경

| 파일 | 역할 | 실제 조치 |
| --- | --- | --- |
| `lib/commerce/product-offer-comparison-v1.mjs` | 신규 공통 계산기 | 상품 ID별 판매처 옵션 검증·같은 구성 묶기·안전한 가격 정렬·링크 허가 구분 |
| `scripts/product-evidence/verify-d8k1-four-seller-comparison-v1.mjs` | 신규 자동 검증 | 0/1/2/4/5개 판매처, 단품/기획세트, 배송비 유무, 품절·미확인, 악성 링크, 미확인 가격, 중복 옵션 등을 가상 데이터로 검증 |
| `scripts/product-evidence/verify-r16i-price-scope-review-v1.mjs` | 기존 자동 검증 연결 | 정해진 Database Integration 검증에서 신규 가격 비교 테스트를 호출·결과 확인 |

기존 `lib/product-offer-read-path.js`는 이미 1개 판매처 링크를 선택하는 보호 규칙이 있으므로 변경하지 않았습니다. **새 계산기에서는 기존 `lib/product-purchase-link.js`의 엄격한 URL 검사 함수를 재사용**, 임의의 URL 문자열을 곧바로 구매 버튼으로 만들지 않습니다.

**변경하지 않은 것:** 추천 엔진 점수/순위, 무료·프리미엄 UI, 분석 API 응답, 제품/Offer DB 스키마·RLS/Auth, 결제·운영 데이터, 실제 판매처 네트워크 연결, 배포·병합.

## 3. 반드시 막아야 하는 오류와 현재 동작

| 위험 | 계산기 처리 |
| --- | --- |
| 상품 ID가 없거나 다른 상품 판매처가 섞임 | 비교에서 배제, 임의 이름 매칭 금지 |
| 추천 허가 상태가 HOLD 또는 미확인 | 구매 비교 전체 HOLD |
| 판매 옵션, 용량, 개수, 증정 상품 구성이 검증되지 않음 | 해당 판매처 가격 비교 제외 |
| 공식몰 80ml 1개 vs 화해 80ml 2개+세럼 | 서로 다른 묶음, 단품 '최저가' 불가 |
| 판매처 가격이 NULL, 0, 음수, 숫자 문자열 | 유효 가격으로 받아들이지 않음 |
| 배송비가 미확인 | 상품 선택 가격순만 표시할 수 있으며 **최종 결제 최저가 배지 비허가** |
| 옛날 가격, 미래 날짜, 관측 시각 불명 | 명시적으로 설정된 신선도 기준 밖이면 제외; 기준 자체가 없으면 과거 관측 표시로 남더라도 직접 구매 버튼 비활성 |
| 쿠팡 링크처럼 현재 직접 URL 보안 규칙에 없는 판매처 | 가격 증거가 있더라도 직접 구매 버튼 비활성 |
| URL이 악성 스킴/가짜 도메인, 또는 판매처 신분과 URL 출처가 충돌 | 링크 비활성 |
| 품절/재고 미확인, 링크 점검 안 됨 | 직접 구매 버튼 비활성 |
| 같은 판매처의 같은 listing ID를 서로 다른 옵션이라고 반복 등록 | **모두 거부**. 현재 DB는 `(seller_key,listing_id)` 1개만 허용 |
| 특정 판매처 상품이 없음 | 해당 판매처를 가짜 행으로 생성하지 않음 |
| 판매처가 네 곳 이상 | 추가 판매처도 데이터 구조상 가능, **보안 승인 없이 신규 URL 직접 연결 불가** |

'증거 확인됨' 같은 입력 필드는 **서버 측 독립 검증을 통과한 데이터만 공급한다는 가상 계약**입니다. 기존 DB 행에 이 값이 존재하지 않으므로, **사용자가 임의로 TRUE를 넣는다고 실제 가격·구매 링크가 승인되는 구조로 운영하지 않습니다**.

가격의 최신성 기준(며칠 이내인지)은 임의로 확정하지 않았습니다. 테스트에서는 가상의 시간 설정을 명시적으로 넣었습니다. 현재 가장 저렴한 판매처라고 확정하는 배지는 기본적으로 항상 차단됩니다.

## 4. 구현 이전 코드와 무엇이 달라졌나

기존 판매처 관련 코드: **검증된 판매처 중 하나의 링크를 선택해 단일 `buy_link`로 반환**하는 부분이 있습니다. 여러 판매처 옵션을 비교하거나 배송비·묶음 구성을 정렬하는 기능은 없습니다.

신규 공통 비교 코드: **같은 카탈로그 상품 아래의 여러 판매처 옵션을 정렬할 수 있지만**, 추천 상품 데이터나 단일 `buy_link` 자체를 바꾸지 않습니다. 직접 URL은 기존 안전 검사 + 새 판매 옵션 신뢰 검사 + 가격 관측 시각/재고/링크 상태가 모두 만족할 때에만 반환할 수 있습니다.

이렇게 분리해야 화해의 묶음상품 결제금액이 단품 대표가격으로 잘못 들어가는 문제를 막을 수 있습니다.

## 5. 검증 명령·통과 기준

```bash
node scripts/product-evidence/verify-d8k1-four-seller-comparison-v1.mjs
node scripts/product-evidence/verify-r16i-r4-d8f-candidate-d4-readonly-prestate.mjs
```

Database Integration Authority의 기존 자동 검사 체인에서도 신규 스크립트를 실행합니다. 추가된 테스트의 출력 단계명은 `D8K1_FOUR_SELLER_OPTION_COMPARISON_SHADOW`이며, 조건은 다음과 같습니다.

- 가상 데이터에서 판매처 네 곳을 올바르게 정렬하고, 단품/기획세트를 분리.
- 악성·미검증·중복 판매처/옵션 가격과 링크 승격 0건.
- 추천 점수/순위 변경 0건, Product/Offer 수정 0건, 분석 API 필드 변경 0건.
- 실제 판매처 가격과 운영 DB 증명 여부는 **false**이며 테스트 통과와 구분.

검증 판정의 근거로 정확한 GitHub Actions commit SHA 및 run을 사용합니다. 실 데이터를 검증하지 않았으므로 완료 상태를 '운영 판매처 비교 적용'으로 바꾸지 않습니다.

## 6. 다음 단계(D8K-2) — 지금 남은 실무 문제

1. **실제 상품과 판매처를 연결할 증거**: 단순한 판매 페이지 URL이 아니라, 선택 옵션·용량·구성·결제금액·관측 시각·판매자 신뢰·상품 ID를 확인해야 합니다.
2. **저장 구조**: 현재 `product_offers` 테이블에는 선택 옵션/배송비/증정 구성 필드가 없고 같은 판매 페이지의 다중 옵션을 별도 저장하기 어렵습니다. 기존 권한·읽기 RPC 재사용을 먼저 검토하고 **DB 변경은 별도 허가 후** 설계/적용해야 합니다.
3. **사이트 표시**: D8K-3 공통 구매처 UI를 만든 뒤 D8K-4에서 활성 무료 Top Pick·프리미엄 루틴/기능성·공유 결과의 실제 상품 카드에 연결합니다.
4. **보안·운영 차단**: 현재 쿠팡, 에스네이처 공식몰 등 미등록 URL을 임의로 신뢰 목록에 넣지 않습니다. 공급망 보안 #1208 문제 해결과 별도 운영 승인 전 병합/배포 HOLD.

**상태 기준:** 공통 비교 계산 **구현**; 실제 판매처 증거/DB read/UI/운영 구매 링크 **미구현**. 테스트와 문서는 실행 근거만 기록합니다.
