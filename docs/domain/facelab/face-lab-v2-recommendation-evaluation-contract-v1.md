# Face Lab V2 Recommendation Evaluation Contract v1

> Track: Face Lab 16 / Recommendation Evaluation System
> Status: Initial deterministic harness contract
> Authority ceiling: synthetic structured-face evaluation only; not real-user truth or production calibration authority

## 1. Purpose

This evaluation layer answers a narrow question:

> Given a structured Face Lab observation plus a confirmed target/scope/constraint state, does the current recommendation engine behave consistently with its own product contracts?

It does **not** claim that a synthetic case represents population prevalence, real user satisfaction, attractiveness, or final production calibration.

## 2. Evaluation boundary

The first harness intentionally starts after image acquisition.

```text
synthetic structured observation
→ FaceLabObservationAnalysis
→ CurrentFaceProfile
→ TargetStyle
→ StyleDelta
→ Routes
→ Domain execution
→ Look Composer
→ Product handoff
→ deterministic evaluators
```

Image generation, real-face calibration, Human review, and LLM Judge evaluation remain separate later stages.

## 3. Locked cohort

Initial locked regression cohort:

- cohort version: `face-lab-v2-locked-regression-cohort-v1`
- seed: `face-lab-v2-eval-v1`
- size: `96`
- source: valid structured observation enums generated by a deterministic PRNG
- authority: regression/stress evidence only

The cohort records a SHA-256 hash so the same seed and harness version can be replayed exactly.

## 4. Hard deterministic evaluation

Initial E1 checks include:

- target authority is available for confirmed direct selections
- route actions never escape requested scope
- whole-domain hard exclusions never survive into route actions
- non-requested direct execution domains remain `not_requested`
- combined grooming request semantics remain bounded to brow/facial-hair scope
- makeup product handoff is absent when makeup execution is not requested
- Look Composer pieces match canonical available execution domains
- selected route authority points to an emitted route

Hard E1 failures block the evaluation verifier.

## 5. Metamorphic registry

### FL-MR-001 — Presentation preference semantic invariance

Changing only masculine/feminine/neutral example preference must not change canonical recommendation semantics.

### FL-MR-002 — Target edit current-face invariance

Changing only the confirmed target must not change `CurrentFaceProfile`.

### FL-MR-003 — Hard exclusion monotonicity

Adding a whole-domain exclusion must remove that domain from route actions and corresponding execution. Grooming remains requested when its other allowed subdomain is still active.

### FL-MR-004 — Minimal change cap

Setting `changeTolerance=minimal` must produce only low-magnitude routes with light-strength route actions.

## 6. Distribution diagnostics

The harness reports, but does not yet gate on:

- selected route strategy counts
- selected route concentration
- action-domain counts
- unique selected action signatures
- action-signature concentration
- no-route count
- canonical status distribution

No arbitrary concentration threshold is frozen in v1. Baselines must be observed before promotion to a blocking quality gate.

## 7. Failure record

Every deterministic failure carries:

- case id
- evaluator id
- optional relation id
- severity
- expected state
- observed state
- likely layer
- stable fingerprint

Later stages may add minimized counterexamples and richer reproduction manifests.

## 8. Deferred stages

Not part of v1:

- property shrinking library integration
- coverage/adversarial cohort families beyond the locked seed cohort
- bounded pairwise LLM Judge
- Human calibration
- real-photo end-to-end evaluation
- production activation threshold

These must remain separate from this initial deterministic authority.
