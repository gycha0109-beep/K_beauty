# Skin Track S4 — Android 앱 실기기 인수 점검 (2026-10-18)

> 대상: S4 Draft #1313. 코드와 CI 검사는 실제 기기의 카메라/네트워크/계정 UAT를 대체하지 않는다. 실사진·계정정보·토큰을 GitHub 이슈/PR/채팅에 첨부하지 않는다.

## APK 종류와 검증 가능 범위

- 기존 `bejewely-mobile-android-debug-<sha>` 산출물은 Gradle Debug APK다. GitHub 에뮬레이터는 별도 **Metro :8081** 서버/adb reverse를 실행하므로 **APK만 휴대폰에 설치하면 독립 실행된다는 보장이 없다**.
- S4 PR 변경에 맞춰 기존 `mobile-android-runtime.yml`이 Android Debug APK 외에 `bejewely-mobile-skin-offline-qa-<PR-head-sha>` 산출물을 조건부 생성한다. 이는 `assembleRelease`로 JS bundle을 내장하되 **운영 배포 서명이 아닌 디버그 키 기반 로컬 QA 목적**의 설치용 테스트 APK다. 스토어 배포 및 Production release 승인 아님.
- **중요:** 오프라인 QA APK 빌드에는 `EXPO_PUBLIC_API_BASE_URL` 및 Supabase 공개 환경변수를 넣지 않는다. 앱이 사전에 서버 구성 부재를 알리고 **실제 분석 전송을 비활성화**하도록 S4에서 보수했다. 따라서 이 APK로 Provider/분석 결과, Google 로그인, 저장 리포트 계정 분리 등 서버 의존 기능을 PASS 판정하지 않는다. 해당 테스트는 별도의 올바르게 구성된 승인 테스트 APK가 필요하다.
- SHA와 `run_id`가 일치하는 GitHub Actions의 **성공한 실제 artifact**만 설치한다. CI 실패/대기 중에는 유효한 APK가 만들어졌다고 주장하지 않는다.

## 첫 테스트 — 오프라인 QA APK (사진 업로드 불필요)

1. 최신 오프라인 QA 산출물을 Android에 설치한다. 이전 설치본과 동일한 앱 패키지 `com.bejewely.mobile`이므로 서명 차이로 설치 충돌 시 이전 테스트 앱을 제거한 뒤 설치한다. **로컬 앱 데이터가 삭제될 수 있으므로 기존 기록이 중요한 기기에서는 이 절차를 하지 않는다.**
2. 앱 실행 → **분석** → Android 카메라 권한 요청: 거부 시 설명 표시, 다시 허용하거나 설정 이동 후 복구 확인.
3. 전면 카메라의 타원 가이드가 보이면 **아무 버튼도 누르지 않고 15초 유지**. 이전 약 1.4~2초 간격의 백색 깜빡임이 없어야 한다. 구형 브랜치는 `takePictureAsync`가 약 1400ms마다 실행되어 preview가 불안정할 수 있었다.
4. `얼굴 위치 확인 (선택)`을 **한 번 누르면 요청한 그 순간에만** 낮은 화질의 로컬 스냅샷 1회가 생긴다. 이 수동 확인 순간의 preview 전환은 기기마다 생길 수 있다. 결과가 '안정화'라면 자세 유지 후 한 번 더 누른다. 이후 10초 동안 **자동 반복 점멸 없어야 함**. 이 결과는 촬영 구도 안내일 뿐 피부 상태 분석 아님.
5. 안내 결과가 불가능하거나 얼굴이 타원 밖이어도 **사진 촬영은 가능**해야 한다. `사진 촬영` → 미리보기 → `재촬영` → `이 사진 사용` → 설문 화면 진입을 확인한다.
6. 설문 필수항목 입력 후 **테스트 앱 서버 설정 없음** 문구가 보이고 **피부 분석 시작이 비활성화**돼야 한다. 이 경우 서버 분석 미수행은 오류가 아니라 QA 빌드의 의도된 차단이다.
7. 앱 내 테마를 라이트/다크로 전환하고 한국어/영어를 바꿔 카메라·설문·안내 문구 잘림/대비/접근성, 복귀 버튼을 확인한다.

## 별도 실제 서버 연결 테스트 — 추후 승인된 API 구성 빌드 한정

1. 먼저 `EXPO_PUBLIC_API_BASE_URL`과 `EXPO_PUBLIC_SUPABASE_URL/ANON_KEY`가 **공개 설정으로 빌드에 반영**됐는지 검사한다. 토큰/서비스 역할 키를 앱에 포함하거나 공개 저장소/채팅에 올리지 않는다.
2. 테스트용 계정으로 로그인/로그아웃과 My의 저장 이력 재진입, 계정 전환 시 전 계정 리포트 노출 여부(비노출 필수)를 확인한다.
3. 서버 구성 오류와 네트워크 끊김 오류를 구별하고, 연결 성공 후에도 분석 POST는 **명시적 사용자 동의·실제 사용 승인 이후**에만 1회 제출한다. 분석 API 요청은 사진 업로드와 유료 Provider 호출 가능성이 있으므로 오프라인 QA에서 실행하지 않는다.
4. 실제 Premium 생성 및 저장 리포트에서 정규화 루틴/기능성/컨디션/HOLD 표시와 web parity를 대조한다. 정확도·재촬영 변화 추론·4개 Skin 허브 UX 전체 동등성은 별도 검증 대상이다.

## 실패 보고 시 필요한 정보

- APK Artifact 이름/commit SHA, 기기 모델과 Android 버전, 화면 위치, 재현 순서, 기대/실제 결과.
- 카메라 백색 점멸 여부를 확인할 짧은 화면 녹화는 **얼굴·인물 사진이 보이지 않게** 카메라를 벽/무인 환경으로 향하거나 본인 비식별 동의 조건에서만 기록. 시스템 로그·스크린샷에는 토큰, 실사진, 사용자 ID, 저장 리포트 본문을 넣지 않는다.
- **PASS 규칙:** CI PASS = 앱 정적/에뮬레이터 계약 PASS; 실제 기기에서 관찰한 점멸 없음 = 해당 기기 UI PASS; 서버/로그인/Provider/개인정보/모델 정확도는 그 자체로 PASS가 되지 않는다.
