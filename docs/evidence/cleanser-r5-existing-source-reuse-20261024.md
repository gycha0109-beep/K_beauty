# R5 이어서 — 화해 기존 성분·리뷰 신호 재사용과 결측 속성 보호 (2026-10-24)

## 1. 한 것

실제 Supabase 클렌저 10개를 **SELECT만** 수행하여 기존 `review_signals`, `ingredient_signals`, `market_signals`가 보유한 집계 차원을 조사했다. 기존 [입력 결측 보고](cleanser-r5-full-engine-input-gap-20261024.md)에서 확인한 **피부타입·피부 고민·제형·마무리감·자극 위험·민감성 적합 여섯 필드는 모두 10/10 결측**이라는 사실은 그대로다.

| 기존 데이터 | 10개 중 존재 | 판정 |
| --- | ---: | --- |
| 원래 화해 리뷰 요약 내 매핑된 기존 점수 입력 | 6 | **기존 `computeReviewSignalScore`에만 재사용** (G2 신규 진입 승인 아님) |
| 화해 리뷰 캡처는 있으나 태그 매핑 없음 | 1 (휩드 머그트리, 전체 리뷰 2) | 기존 정규화 도구에서 품질 재검토 |
| 화해 캡처 미기록 | 3 | 원래 상품·화해 ID 연결 확인, 수집권 확인 전 신규 수집 없음 |
| 성분 집계의 피부 타입 축·기능 축·위험도 축 | **7** | 기존 성분 점수식의 **집계 근거**, 실제 개별 상품의 피부타입 적합·안전성 Fact 아님 |
| 피부타입/고민/제형/마무리감/자극/민감성 여섯 **정본 메타데이터** | **0** | 이름·리뷰 문구·성분 위험 집계로 억지 변환 금지 |

출처·표본·국가별 실제 제품 일치 검토는 여전히 필요하지만, **새로운 `reviewed_by` 필드나 제조사 회신을 일반 리뷰 점수 재사용의 선행 조건으로 추가하지 않는다**.

- [민감정보 없는 기존 출처 차원 집계](../../evidence/trust/cleanser-r5-existing-source-axis-footprint-20261024-v1.json)
- `lib/trust/cleanser-r5-existing-source-evidence-routing-v1.mjs`: **6/1/3 경로와 7개 성분·시장 집계**를 원본 데이터 그대로 구별한다. 실제 Product Fact 또는 신규 추천 순위를 승인하지 않으며, 열 가지 제품 모두의 여섯 결측 메타데이터를 가짜 값으로 채우지 않는다.
- `scripts/verify-cleanser-r5-existing-source-evidence-routing-v1.mjs`: 기존 숫자형 집계 10개, 상품 ID 매핑, 링크 문자열/원본 변경/위조된 승인 상태에 대해 fail-closed 테스트 추가.
- `scripts/run-cleanser-r5-private-full-engine-readonly-v1.mjs`: **명시적으로 허가된 비공개 서버 환경에서만** 전체 화해 요약 원본 문자열을 메모리에 일시 로드해 실제 Skin Match를 164+10×12로 계산할 수 있게 만든 GET-only 도구. `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` 필요. **공용 CI·공개 URL·로그에 원문/자격증명 기록 금지. 현재 이 도구를 운영 인증정보로 실행한 실증은 아님.** 정식 G2 차단을 유지하고 새 10개 점수·순위는 출력하지 않으며 164개 원래 점수 불변·컴포넌트 계산 일치의 요약만 기록하도록 설계.

## 2. 남은 것

- 10개 실제 판매 상품의 메타데이터 6개는 검증된 값이 없다. **현재는 0/60 근거 기반 작성 가능**으로 구분하고, 누락은 거짓 Fact가 아니라 `UNKNOWN`으로 관리한다.
- 실상품 원본을 사용하는 비공개 전체 엔진 재실행 및 원래 화해 ID·용량 매핑의 일치 확인이 남아 있다.
- 리뷰·성분 집계가 있다고 `skin_types`를 자동 설정하거나 성분 위험 집계가 곧 저자극 테스트라고 판단해서는 안 된다.

## 3. 다음 작업과 블로커

1. 보호된 서버에서 GET-only 전체 엔진 재계산을 수행해 실제 신호가 정확히 한 번씩 더해지는지 확인하고 **기존 164개 점수 불변**을 증명한다. 비공개 인증정보를 공개 CI에 전달하지 않는다.
2. 동일한 기존 관리 도구/캡처 파이프라인에서 6개 메타데이터의 근거 수준을 판단하고, 제품별 의심되는 국가·용량 오매칭과 리뷰 2개/캡처 없는 세 상품을 우선 점검한다. 모든 필드를 반드시 채우기 위해 추측하지 않는다.
3. 제한 추천 전환에는 별도의 보호된 G2 정책 검토, 사용자에게 데이터의 불확실성 표기, 법적 수집·활용 범위와 롤백 검증이 필요하다.
