> **출처**: BEJEWELY 현재 Supabase `products`의 10개 기존 클렌저 행을 읽기 전용으로 조회한 **원본을 제외한 축약 결과**. 제조사 연락, 화해 페이지 신규 크롤링, 서비스 G2 전환 또는 상품 메타데이터/DB 수정은 수행하지 않음.

> **분류 의미**: "점수식 입력 후보"는 기존 `computeReviewSignalScore`가 읽을 수 있는 값이 저장되어 있다는 뜻이지 최종 적합성 점수 검증, 정식 추천 승인, 공식 Fact 확정이 아니다.

- **매핑되지 않은 AI 요약 문구**는 실제 Skin Match 코드에서 `normalizeReviewSignals`이 다시 파생 태그를 시도할 수 있다. 따라서 이 표의 6/1/3은 **기존 DB에 저장된 태그를 기준으로 한 보수적 구조 분류**이지 실제 런타임 계산값의 확정 결과가 아니다.

## 이번 변경의 실제 범위

1. [축약 실데이터 증거 파일](../../evidence/trust/cleanser-existing-hwahae-signal-footprint-20261024-v1.json): 상품 UUID, 리뷰 수, 상위 매핑 개수, 갱신일·출처 상태만 보존. AI 요약 라벨과 리뷰 원문·URL·전성분 원본은 GitHub에 저장하지 않음.
2. `lib/trust/cleanser-hwahae-existing-score-shadow-v1.mjs`: **정본** `lib/review-signals.js`의 `normalizeReviewSignals`, `computeReviewSignalScore` 직접 재사용. 날짜와 검토자가 별도 테이블에 없더라도 기존 데이터 스키마로 입력 가능. 세 피부 맥락별 `review_signal_score`만 Shadow 출력. 기존 전체 Skin Match 최종 점수와 구분.
3. `scripts/run-cleanser-existing-hwahae-live-review-score-v1.mjs`: **승인된 서버에 한하여** 기존 10개 원본 데이터를 HTTPS Supabase 테이블 GET만으로 읽고 위 함수를 그대로 계산해 숫자/보류 사유만 출력하는 프로그램. 서비스 키는 CI/공개 저장소에 입력하거나 출력하지 않음. 실제 운영 DB에 이 프로그램을 실행하지는 않았으므로 아직 실상품 정밀 점수는 미완료.
4. `scripts/verify-cleanser-hwahae-existing-score-shadow-v1.mjs`: 원본 제거된 10개 DB 집계와 **합성** 샘플을 통한 정본 점수식 호환성·누락·URL 오매칭·카테고리 오입력·Fact/G2 승인 금지 테스트.

## 남은 일 및 허가 경계

- 실제 운영 비밀번호를 공개 GitHub CI에 넣지 않고, 허용된 서버 환경에서 기존 신호 **7건을 기존 함수로 정확히 재생**하고 전체 Skin Match 점수식의 `ingredientSignalScore`·`marketConfidenceScore`·`reviewSignalScore`를 이중 집계하지 않는지 확인한다.
- 라곰 서로 다른 용량/지역 상품을 무단으로 동일 상품으로 병합하지 않는다. 화해 원본 수집이 없는 3개는 `MISSING_CAPTURE` 원인을 검토하되 사이트 이용권 확인 없는 반복 수집이나 크롤링 우회는 하지 않는다.
- 별도 `reviewed_by` 스키마·독자적 승인 프로세스를 **지어내지 않는다**. 신뢰도는 기존 `review_signals`의 점수계약과 품질 검증으로 평가하고, 정식 효능 Claim은 보호된 PF-1 Fact 트랙에서만.
- 기존 운영 G2 클렌저 진입/추천·RLS·DB 업데이트·배포 변경 **0건**. 제한적 추천 후보 진입은 별도의 G2 권한/Canary 승인 뒤 진행.
