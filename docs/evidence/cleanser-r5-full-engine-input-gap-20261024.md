# R5 신규 클렌저 전체 Skin Match — 실상품 입력 누락 점검 (2026-10-24)

> 이 문서는 R5 진행 결과의 **안전성/한계** 기록이다. 실서비스 신규 추천 승인이나 사용자 적합도 확정 자료가 아니다.

## 실제 DB 확인: 클렌저 10개 모두 핵심 속성 6종이 비어 있음

Supabase `public.products` / `catalog_trust_intake`의 기존 10 Product ID를 **SELECT-only** 조회한 결과, 다음 속성은 10개 전부 `NULL` 또는 빈 값이다.

| 클렌저 추천에 필요한 속성 | 실제 값이 있는 상품 |
|---|---:|
| 피부 타입(`skin_types`) | 0/10 |
| 피부 고민(`concerns`) | 0/10 |
| 제형(`texture`) | 0/10 |
| 사용 후 마무리(`finish`) | 0/10 |
| 자극 위험(`irritation_risk`) | 0/10 |
| 민감성 적합(`sensitivity_safe`) | 0/10 |

이 값이 없는 것을 **낮은 품질·안전하지 않음·효능 없음**으로 간주하지 않는다. 현재 `buildRecommendationProductFromSource`는 일부 필드를 기본값(피부 타입 combination, 고민 dehydration 등)으로 채운다. 이 **자동 기본값이 곧 해당 신제품의 실제 특성을 입증하지는 않는다.**

## R5 실제 엔진 검증 방식

- [원본 데이터 제외한 제품 필드 현황](../../evidence/trust/cleanser-r5-real-input-coverage-20261024-v1.json)을 CI 고정 입력으로 사용한다.
- `scripts/verify-cleanser-r5-full-engine-redacted-shadow-v1.mjs`는 **기존 164개 실제 추천 fixture + 신규 클렌저 10개**를 `buildRecommendationProductFromSource`로 정규화해, *기존 Skin Match 엔진을 12개 시나리오에 실제 실행*하는 격리 테스트다.
- 원래 164개에 대해서는 **신규 10개를 붙이기 전과 후에 전체 점수·세부 점수·decision_meta가 동일**해야 한다. 전체 후보 순위/선택에는 신규 10개가 끼어들 수 있어 **실제 사용자에게 이 174개 테스트 결과를 노출하지 않는다**.
- 테스트 입력의 화해 리뷰 AI 요약 **문구는 보안/이용권을 위해 GitHub에 저장하지 않는다**. 이 문구를 제거하고 저장된 `mapped` 태그만 남긴 입력으로 실제 원본 점수식을 시험했더니 **기존 6개 × 3개 조건 중 13칸의 비영점 점수가 0으로 바뀌었다**. 그러므로 리뷰 문구가 제거된 테스트 자료로 신규 10개의 **정확한 최종 점수·순위를 확정할 수 없다**.
- [기존 실제 리뷰 보정점수 리플레이](../../evidence/trust/cleanser-actual-review-score-replay-20261024-v1.json)는 여전히 정확하며, 별도 안전하게 읽어야 한다. **축약 리뷰 신호를 본 점수식에 대신 집어넣으면 안 된다**.
- `low_ph` / `deep_cleansing` 은 이 검증으로 공식 Fact가 되지 않는다. 실제 G2 클렌저 추천은 계속 `NO_GRANT`다.

## 남은 작업 순서 (R5 → R6)

1. **R5-1** 전체 엔진 무결성: 164 × 12 원래 후보 점수 불변 / 누락 10개 임시 기본값 경고 / 실제 추천 노출 0 테스트를 통과시킨다.
2. **R5-2** 기존 화해 원본이 있는 안전한 서버 내에서만 10개 신규 상품의 **실제 리뷰 원본 + 실제 DB 구조화 필드**를 넣어 전체 Skin Match 계산을 수행하고, 리뷰/성분/시장 점수의 중복 여부·정합성을 검증한다. **원본 리뷰 문구, URL, 서비스 키는 공용 GitHub에 업로드하지 않는다**.
3. **R5-3** 기존 카탈로그 메타데이터 정규화 파이프라인을 확인해 피부 타입/고민/제형/마무리 등의 결측을 근거에 따라 보완할 필요가 있는지 결정한다. 확인 불가능한 필드를 일반적 기본값으로 확정 Fact처럼 덮어쓰지 않는다.
4. **R6** 보호된 G2의 제한 진입 정책, 설명 문구, 권한·보안, 기능 플래그, 롤백, 활용 권리 및 운영 승인 후에만 새 상품 추천 진입.

**현재 승인 경계:** DB 수정·Subject/Source/Fact 승인·G2 허용 변경·배포·운영 추천 반영 **0건**. 현재 PR은 #1401 기반 Draft로 별도 개발 중.
