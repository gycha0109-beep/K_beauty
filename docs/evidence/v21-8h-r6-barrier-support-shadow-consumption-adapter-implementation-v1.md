# V2.1-8H-R6 — 배리어 지원 그림자 소비 어댑터 구현

## 종료 판정

`BARRIER_SUPPORT_SHADOW_CONSUMPTION_ADAPTER_IMPLEMENTATION_VALIDATED`

R6는 R5 계약을 그대로 구현한다. R4의 배리어 지원 비수치형 의사결정축을 사용자 배리어·탈수 문맥과 연결하지만, 결과는 기존 후보 노출 정책의 **별도 그림자 출력**으로만 존재한다.

## 구현

- 새 모듈: `lib/barrier-support-non-numeric-pda-shadow-adapter.js`
- 그림자 연결: `lib/candidate-exposure-policy-shadow.js`
- 입력 자료: R4 전체 상품 176개 오프라인 출력
- 사용자 문맥: 설문 `mainConcern/mainConcerns` 우선, 없을 때만 현재 우선 축을 보조 입력으로 사용
- 관련 축: `barrier`, `dehydration`

기존 후보 정책 평가기에는 배리어 그림자 결과를 전달하지 않는다. 기존 정책 결과, 응답, 저장 스냅샷, 후보 순서는 기존 경로 그대로 유지한다.

## 의미론

- 참은 공식 배리어 지원 주장 확인이다. 효과 강도가 아니다.
- 명시적 거짓은 부정 주장 상태일 뿐 효능 부재나 부적합 판정이 아니다.
- 미확정은 거짓으로 채우지 않는다.
- 차단은 미확정으로 완화하지 않는다.
- `primary_use_role`은 문맥 전용이다.
- `local_area`는 후보 자격을 변경하지 않는다.
- `full_face`는 더 강한 효과를 의미하지 않는다.
- 배리어와 탈수가 동시에 관련돼도 하나의 비가산 설명 문맥으로만 유지한다.
- 범위와 계보를 그대로 보존하며 범위를 자동 선택하지 않는다.

## 검증

집중 검증기는 R5의 12개 계약 사례를 실제 어댑터 함수로 정확히 재생한다. 또한 R4 전체 176개를 배리어·탈수 관련 문맥으로 투영해 다음 분포를 확인한다.

- 설명 가능한 공식 주장: 6
- 명시적 거짓 주장: 0
- 사실 미확정 보류: 14
- 차단: 51
- 비적용: 105

R4의 6개 실제 참 상품은 사실 범위와 계보를 손실 없이 전달해야 한다. 숫자 기여, 순위 영향, 후보 자격 영향은 모두 0이다.

그림자 어댑터 자체 실패는 기존 후보 정책 실행과 격리한다.

## 추천 불변성

기존 승인 후보 164개 × 사용자 상황 12개 = 1,968건의 실제 추천 회귀 검증 책임은 `BEJEWELY Current Main Health`가 유지한다. R6는 그 분모를 확대하거나 교체하지 않는다.

- 점수 변화: 0
- 순위 변화: 0
- 1위 변화: 0
- 상위 3개 변화: 0
- 후보 자격 변화: 0
- 후보 정책 변화: 0
- 공개 응답 변화: 0
- 저장 변화: 0

## 운영 경계

운영 DB 쓰기, 레지스트리 변경, 마이그레이션, 추천 활성화는 없다. Production에서는 기존 그림자 제어 자체가 하드 비활성 상태다.
