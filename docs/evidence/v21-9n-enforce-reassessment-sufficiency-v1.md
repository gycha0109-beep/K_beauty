# V2.1-9N ENFORCE Reassessment Sufficiency Governance Contract

## 1. Stage boundary

V2.1-9N closes the governance gap identified by V2.1-9M:

`ENFORCE_REASSESSMENT_SUFFICIENCY_POLICY_REQUIRED`

This Stage does not perform ENFORCE reassessment, authorization, activation, or Production traffic generation. It does not mutate Product Fact, durable Production evidence, Recommendation semantics, CandidatePolicy, or Production runtime controls.

## 2. Primary outcome

`ENFORCE_REASSESSMENT_SUFFICIENCY_CALIBRATION_REQUIRED`

This is a successful governance outcome, not a blocker.

A deterministic non-numeric policy can freeze integrity prerequisites and qualitative evidence categories, but it cannot distinguish a single thin organic execution from empirically mature natural operation without importing an ungoverned threshold.

Therefore V2.1-9N freezes calibration parameters and authority boundaries, not numeric values.

1. `EVIDENCE_EXISTENCE`
2. `EVIDENCE_INTEGRITY`

`READY_FOR_SEPARATE_ENFORCE_REASSESSMENT != ENFORCE_AUTHORIZED`

## 4. Integrity prerequisites

The following are hard prerequisites, not evidence-volume thresholds:

- Production effective mode remains SHADOW and runtime is active.
- `enforcementAllowed = false`.
- `enforceActive = false`.
- `restrictCanonicalExclusionActive = false`.
- provenance source partition is explicit.
- controlled Production evidence remains separate from organic evidence.
- UNKNOWN evidence is never promoted into organic evidence.
- runtime version and activation scope are compatible.
- mixed incompatible version groups are absent.
- SHADOW actual exclusion is zero.
- no `stopRequired` integrity failure exists.
- canonical Recommendation invariance reference remains valid.
- Hosted Product Fact authority remains stable.
- durable store/readback authority remains healthy.

Evidence quantity can never override an integrity failure.

Category presence is not maturity.

## 6. Zero versus unobserved

After real organic execution:

- runtime error count `0` is characterized zero.
- fallback count `0` is characterized zero.

Before any organic execution:

- runtime error count `0` is unobserved.
- fallback count `0` is unobserved.

`zero != missing`

## 7. Action coverage

Frozen action vocabulary:

- ALLOW
- CAUTION
- RESTRICT
- DEFER
- NOT_APPLICABLE

V2.1-9N does not require all five actions to occur.

Organic action evidence exists when the policy engine has produced governed action evidence under organic execution. The absence of RESTRICT, DEFER, or CAUTION is not proof that safety-relevant paths are sufficiently covered.

The required maturity of safety-relevant branch coverage is an empirical calibration parameter.

## 8. Context diversity

Governed independent context marginals:

- PRIMARY_CONCERN_CLASS
- SENSITIVITY_RISK_CLASS
- CONCERN_STRUCTURE_CLASS
- SURVEY_COMPLETENESS_CLASS
- RECENT_INSTABILITY_CLASS

Qualitative context evidence exists when organic operation has populated the governed independent marginal dimensions.

V2.1-9N does not join marginals, reconstruct users, build composite fingerprints, or require an invented number of bucket values.

Marginal presence is not mature breadth. Required breadth is an empirical calibration parameter.

## 9. UNKNOWN source policy

Explicit UNKNOWN evidence is not silently treated as organic.

`UNKNOWN > 0` is not frozen as a permanent integrity failure merely because the count is non-zero. If provenance remains explicit and separation is intact, UNKNOWN is characterized evidence whose acceptable future tolerance requires calibration.

Misclassification, loss of provenance, or promotion of UNKNOWN into organic evidence remains an integrity failure.

## 10. Runtime errors and fallback

A non-zero runtime error or fallback count is not automatically declared acceptable or unacceptable by an invented tolerance.

Hard stop reasons, canonical invariance failures, or forbidden SHADOW actual exclusion remain integrity blockers.

The tolerance separating isolated occurrence from systematic instability requires empirical calibration.

## 11. Authority hierarchy

### Level 1 — Frozen BEJEWELY governance invariant
Can establish hard prerequisites, qualitative requirements, and the calibration methodology boundary.

### Level 2 — Observed canonical system behavior
Can establish actual runtime/version/invariance state and qualitative behavior evidence. It does not create a maturity threshold by itself.

### Level 3 — Controlled validation evidence
Can validate instrumentation, mechanics, edge behavior, and deterministic contracts. It cannot substitute for organic Production maturity.

### Level 4 — Organic Production evidence
Is the primary empirical authority eligible to calibrate maturity criteria when used under a previously frozen methodology and separately validated.

### Level 5 — External scientific/industry reference
May inform statistical or rollout methodology. It cannot become a BEJEWELY numeric threshold by itself.

### Level 6 — Pure operator preference
Cannot independently authorize a hard prerequisite, sufficiency criterion, or numeric threshold.

No external reference was required to freeze V2.1-9N.

## 12. Why a purely non-numeric READY policy is rejected

A policy containing only:

- integrity PASS
- organic traffic present
- action evidence present
- context evidence present
- runtime behavior characterized
- stable versions
- non-empty observation window

can be satisfied by one organic execution because one execution can populate action, context, zero-error, zero-fallback, and window-presence fields.

Treating that boolean completeness as reassessment-ready would silently encode:

`one category-complete event is sufficient`

No frozen BEJEWELY authority supports that rule.

Therefore outcome A is rejected for V2.1-9N.

## 13. Frozen calibration contract

Contract version:

`enforce-reassessment-sufficiency-calibration-contract-v1`

Parameters requiring future empirical calibration:

- minimum observation horizon
- minimum organic execution volume
- required temporal recurrence
- required context breadth
- required safety-relevant branch coverage
- UNKNOWN source tolerance
- runtime error tolerance
- fallback tolerance
- stability criterion

No values are assigned in V2.1-9N.

### Authorized input roles

- future organic durable SHADOW evidence: primary maturity-calibration evidence
- controlled Production evidence: instrumentation/edge validation only
- synthetic simulation evidence: regression/stress only
- historical privacy-safe projections: diagnostic unless separately governed
- external reference: methodology only
- operator preference: insufficient as sole authority

### Methodology constraints

- freeze the calibration method before the validation window.
- separate calibration data from validation/holdout evidence.
- version and lock the resulting policy artifact.
- do not choose thresholds retroactively to make current evidence pass.
- do not reconstruct unique users.
- do not join marginals into composite fingerprints.
- do not substitute controlled/synthetic evidence for organic maturity.
- every threshold or criterion must retain explicit authority lineage.
