작업명:
Phase 44 — Local Shadow Runtime Reproducibility & Provider Isolation Implementation

목표:
Phase 43에서 `blocked_local_schema_not_reproducible`로 중단된 isolated shadow route 환경을 로컬에서 재현할 수 있도록 구현한다.

이번 단계에서는 실제 `/api/analyze` flag-off/flag-on route 요청을 실행하지 않는다.
로컬 bootstrap, provider isolation, mutation observer, cleanup 및 직접 검증까지 완료한 뒤 controlled route run 직전 상태를 만든다.

이번 delta:

1. 로컬 Supabase 재현성
- 현재 migration만으로 fresh local schema가 재현 가능한지 먼저 확인한다.
- 충분하면 기존 migration을 그대로 사용한다.
- 불충분하면 production migration을 수정하지 말고 test-only bootstrap을 만든다.
- test-only 파일은 `supabase/local-shadow-test/` 같은 격리된 경로에 둔다.
- route 실행에 필요한 최소 table, enum, RPC, function, storage metadata만 재현한다.
- schema contract를 실제 코드에서 확정할 수 없으면 추정 구현하지 말고 `blocked_local_bootstrap_contract_gap`으로 중단한다.

2. Provider isolation seam
- default-off인 development 전용 provider stub을 구현한다.
- 명시적 flag, `NODE_ENV === "development"`, loopback/disposable local target 확인이 모두 필요하다.
- flag가 꺼져 있으면 기존 provider resolution과 동작이 바뀌지 않아야 한다.
- flag가 켜져 있으면 `.env.local` fallback이나 실제 provider SDK/fetch보다 먼저 deterministic stub이 선택돼야 한다.
- 실제 provider 호출은 0이어야 한다.
- stub 결과는 현재 provider result contract와 호환돼야 한다.
- route response shape, 추천 결과 구조, score/filter 정책은 변경하지 않는다.
- evaluator 또는 CandidatePolicy를 runtime에 연결하지 않는다.

3. Deterministic fixture 및 seed
- 실제 사용자 이미지와 인터넷 얼굴 이미지를 사용하지 않는다.
- provider stub과 함께 사용할 synthetic fixture를 사용한다.
- 실제 제품명, 브랜드, 구매 URL, 리뷰 원문을 복제하지 않는다.
- 최소 비교가 가능한 deterministic synthetic product/session 데이터를 사용한다.
- seed는 반복 실행해도 동일한 결과가 나와야 하며 cleanup 가능해야 한다.

4. Mutation observer
- production migration에 추가하지 않는다.
- local test DB에만 ephemeral audit schema/trigger 또는 동등한 observer를 설치한다.
- table/schema/operation/count와 정규화된 식별 정보만 기록한다.
- row 원문, PII, secret, 제품명, URL, 리뷰 원문은 기록하지 않는다.
- RPC 내부 mutation도 가능한 범위에서 포착한다.
- Storage mutation과 filesystem shadow artifact는 DB mutation과 분리해 관측한다.
- observer coverage가 불충분하면 PASS 처리하지 않는다.

5. Setup / teardown
- local environment setup, seed, observer 설치를 한 명령 흐름으로 재현 가능하게 만든다.
- teardown은 seed, audit schema/trigger, local storage object, tmp artifact, 관련 process를 정리한다.
- teardown은 두 번 실행해도 안전해야 한다.
- `.env.local`을 덮어쓰지 않는다.
- 필요한 환경값은 현재 process 범위에서만 주입한다.

6. 기존 harness 연결
- 기존 isolated comparison harness를 최대한 재사용한다.
- 이번 단계에서는 실제 route invocation을 하지 않는 준비/검증 모드를 명확히 분리한다.
- 기존 harness를 대규모 재작성하지 않는다.
- setup, verifier, teardown이 controlled route run 단계에서 그대로 재사용될 수 있게 한다.
